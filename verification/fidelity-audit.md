# Проверка совпадения звука ViPER

Текущая Windows-версия сохраняет многие исходные алгоритмы ViPER. Однако одинаковое звучание всей цепочки 1:1 не подтверждено: ряд эффектов и их порядок изменены. **Для многих эффектов принципы обработки сохранены; для Tube алгоритм заменён, а для некоторых ранее незавершённых эффектов появился рабочий алгоритм.** Если требуется максимально воспроизвести старый модуль, нужен отдельный режим исходного ядра и порядка обработки, включая старый лимитер и особенности старого кода. Такого режима в текущей сборке нет. Системный APO из комплекта использует современное ядро.

Проверка выполнена 7 октября 2026 года. Сравнены исходники RE 0.6.1 и используемое ядро ViPERDSP db1c11c. Старое ядро собрано для контрольного расчёта без изменения алгоритмов; заглушено только Android-логирование и добавлены стандартные заголовки. Отдельно статически проверены функции из приложенного ELF-модуля. Это не запись звука с Android и не доказательство полного совпадения исходников с каждым Android-бинарником.

Метод: стереосигнал из семи тонов и фиксированного шума, две отдельные серии при 44 100 и 48 000 Гц, блоки по 480 кадров, четыре секунды. При проверке отдельных эффектов старый лимитер исключён, современная задержка в 256 кадров компенсирована. Первые две секунды исключены из численных результатов. Поэтому точное совпадение ниже относится к отдельному эффекту на проверенном сигнале, после начального переходного процесса. Оно не означает побитового совпадения готовых WAV, системного выхода или любого пресета.

| Эффект | Результат |
|---|---|
| Эквалайзер, DDC, Spectrum Extension, Differential Surround, Dynamic System | Отсчёты совпали в отдельных тестах при 44,1 и 48 кГц. DDC после сброса может иметь другой переходный процесс: современное ядро очищает больше состояния. |
| Clarity Natural/XHiFi, Cure все 3 режима, AnalogX все 3 режима, Speaker optimization | Отсчёты совпали после начального переходного процесса при обеих частотах. AnalogX сохраняет примерно 250 мс тишины после включения. |
| Clarity Ozone | Отношение RMS разности к RMS контрольного сигнала — примерно 3,5 × 10⁻⁸ при обеих частотах; математическая структура сохранена. |
| Bass Subwoofer | Почти совпал установившийся выход, но стартовое плавное включение изменено. |
| Bass Natural/Pure | Сохранён основной фильтр/полосы, добавлены блокировка постоянной составляющей с частотой 18 Гц, сглаживание за 30 мс и мягкое насыщение. Отсчёты и частотный ответ отличаются; слышимость разницы в слепом прослушивании не проверялась. |
| Field Surround | Сохранена идея, исправлена задержка: старый код фактически работал со смещением 0, новый использует 20/14 мс. Ответ отличается. |
| Reverb | Сохранена схема comb/allpass, исправлен обход стереобуфера. Старые перекрывающиеся записи и новый правильный стереопроход дают разный результат. |
| Playback Gain/AGC | Старый исходник анализировал звук, но не применял усиление. Современный действительно регулирует усиление. |
| Tube Simulator | Алгоритм заменён: старое усреднение на чередующихся кадрах и новая фильтрованная гармоническая обработка не совпадают. |
| Master Limiter | Изменены ограничение и огибающая; задержка 255 → 256 кадров. Даже без срабатывания старый выход в тесте примерно на 0,0174 дБ тише. |
| Convolver, VHE, FET | В старом исходнике соответствующие части не завершены; в новом работают. Это функциональное расширение, а не идентичное воспроизведение старых заглушек. |

В приложенном x86_64 бинарнике подтверждены конкретные признаки исходного кода: FET Process состоит из `ret`; PConvSingle ProcessKernel возвращает 0; PlaybackGain Process не пишет в аудиобуфер; Tube использует усреднение на чередующихся кадрах; TimeConstDelay вызывает `modff`. В JSON также записаны хеши и сведения о символах библиотек arm64-v8a, armeabi-v7a и x86. Библиотеки Android не выполнялись: эти признаки не подменяют динамический тест каждого эффекта на устройстве.

Порядок старых групп в RE 0.6.1: `DDC → VSE → EQ → Field → Diff → Reverb → Speaker → AGC → FET → Dynamic → Bass → Clarity → Cure → Tube → AnalogX → Gain/Pan → Limiter`.

В текущем ядре: `DDC → VSE → EQ → Field → Diff → AGC → FET → Dynamic → Tube → Bass → Clarity → Cure → AnalogX → Reverb → Speaker → Gain/Pan → Limiter`. Перед этими цепочками стоят Convolver/VHE. Дополнительные современные группы выключены. Перестановка особенно влияет на сочетание нелинейных эффектов.

Параметры интерфейса и преобразования ползунков сохранены из APK. Например: выход 100%, pan 0, limiter 100%, bass 70 Гц / 0,5, clarity 0,5, depth 200 / mid image 1,5, Differential 5 мс. Совпадение значений управления не устраняет изменения внутри алгоритмов. IRS другой частоты автоматически пересчитывается; для ближайшего совпадения следует использовать исходный IRS с той же частотой.

Отдельно проверена цепочка с лимитером. Даже при выключенных остальных эффектах после выравнивания задержки остаётся указанная разница усиления. В составном пресете с несколькими эффектами выход отличается заметно сильнее; точное совпадение отдельных фильтров этого не устраняет.

Численные результаты для обеих частот, конкретные команды, хеши библиотек и контрольных исходников находятся в [fidelity-audit.json](fidelity-audit.json). Исходная ветка RE 0.6.1 не закреплена идентификатором коммита; содержимое использованных файлов зафиксировано контрольной суммой в отчёте. Слепое прослушивание и запись Android-устройства не проводились. Процент «общего сходства звука» здесь не рассчитывается: такая цифра была бы недостоверной.
