# ViPER4Windows-RE — адаптация ViPER4Android-RE 0.6.2 для Windows

Порт воспроизводит настройки приложенного APK и обрабатывает звук настоящим восстановленным движком ViPERDSP. Перенесены **18 разделов, 45 параметров, 12 пресетов эквалайзера и 23 варианта Dynamic System**, исходные значения и преобразования регуляторов. С учётом переключателей разделов сохраняются 63 настройки. Интерфейс адаптирован к ПК; побитовое совпадение звука с Android-модулем 0.6.1 не заявляется.

## Запуск

1. Распакуйте **всю папку** в доступное для записи место, например «Документы». Сохраните рядом `ViperDsp.dll`, папки `icons` и `drivers`.
2. Запустите **`ViPER4Windows-RE.exe`**. Сборка для Windows x64 содержит .NET 8: отдельно устанавливать .NET не нужно.
3. На странице «Эффекты» выберите профиль, включите нужные разделы и общий переключатель **«Обработка»** справа вверху. По умолчанию обработка выключена, как в исходном APK.
4. Выберите способ подачи звука на странице **«Звук»**. Одно открытие приложения ещё не направляет через него звук Windows.

Для обработки WAV, входного потока и уже подготовленного устройства ViPER права администратора не нужны. Они могут понадобиться при подготовке устройства и подключении APO. Закрытие окна по умолчанию сворачивает приложение в трей; полностью выйти можно через меню значка в трее или «Настройки → Закрыть приложение». На странице «Звук» можно отдельно включить запуск системного маршрута при открытии программы.

## Виртуальное устройство ViPER

На этом ПК подготовлено устройство **ViPER (FxSound Audio Enhancer)** на основе уже установленного подписанного виртуального драйвера FxSound. Это существующий драйвер с новым именем; новый собственный драйвер ядра не создавался. Приложение FxSound должно быть закрыто.

1. Откройте «Звук». Выберите ViPER для звука приложений и физические наушники или колонки для обработанного выхода.
2. Нажмите «Запустить системный звук». Программа переключит выходы Windows на ViPER и направит обработанный поток на выбранный физический выход.
3. Включите «Обработка» и настройте эффекты. Раскрытие разделов и обновление страницы сохраняют положение списка.
4. При остановке и полном выходе возвращаются прежние устройства Windows. При аварийном завершении это делает отдельный помощник. Приложения, в которых вручную задан другой выход, нужно направить на ViPER; исключительный режим и защищённые потоки через этот маршрут не гарантируются.

Обработка идёт в float32, стерео, 48 кГц. WASAPI выполняет преобразование частоты и каналов при необходимости. Конечный поток использует RAW, чтобы пропустить эффекты потока и режима на физическом устройстве; обработка самого оборудования может оставаться. Частота потребления выходного потока плавно корректируется для синхронизации часов устройств. Побитовое совпадение при таком маршруте не заявляется. На проверенном ПК общая задержка тестового сигнала составляла примерно 80–100 мс.

Если физический выход не поддерживает RAW (ошибка `0x88890027`), программа автоматически использует обычный общий режим Windows. Это требуется, например, для проверенного Focusrite USB Audio. Эффекты ViPERDSP сохраняются; эффекты самого выходного устройства могут оставаться, что указано в состоянии потока. Если на таком выходе назначен активный ViPER APO, запуск блокируется с понятной инструкцией, чтобы звук не обрабатывался повторно. Для обычного режима предусмотрен больший запас буфера; задержка зависит от интерфейса и может быть выше измеренной на Realtek.

На виртуальном входе снято прежнее назначение ViPER APO, чтобы обработка не выполнялась дважды. Исходные значения сохранены в `data/driver-backups`. Кнопка «Вернуть имя устройства» возвращает имя FxSound; назначение APO восстанавливается отдельно из резервной копии. Для первого использования уже назначенного входа нажмите «Назвать устройство ViPER» и подтвердите запрос Windows.

Громкость, баланс каналов и отключение звука виртуального выхода учитываются. Если драйвер не поддерживает захват после системной громкости, программа считывает уровни каналов и применяет их в обработке. Микрофон для системного маршрута не открывается.

## Способы обработки

| Режим | Как пользоваться | Что проверено и что требуется |
|---|---|---|
| Все приложения → виртуальный ViPER → физический выход | «Звук → Запустить системный звук» | Проверено на ViPER/FxSound → Realtek: бас и EQ меняют физический выход; переключение, восстановление после остановки и сбоя, громкость и mute проверены. За 120 с обработано 5,77 млн кадров без пропусков и нехваток. |
| WAV → обработанный WAV | «Звук → Выбрать WAV и обработать…» | Реальная обработка и сохранение проверены; отдельный системный драйвер не нужен. |
| Вход → ViPER → выход | Выберите устройство записи и устройство воспроизведения, нажмите «Запустить поток» | Реализован WinMM-поток: 48 кГц, стерео, PCM 16 бит, блоки 10 мс. Нужен микрофон, линейный вход или виртуальный кабель. На этом ПК запись и прослушивание при проверке не запускались. |
| Все приложения через APO | Установите и зарегистрируйте отдельный драйвер по инструкции ниже | Установленный APO сверён с комплектным установщиком. После обновления аудиослужбы Windows загрузила его DLL: драйвер подтвердил 48 кГц и обработал 233 280 кадров на Realtek. Отдельное сравнение баса/EQ для APO после обновления не выполнялось. Для виртуального маршрута APO не нужен. |

**WAV.** Поддерживаются RIFF WAV с PCM 8/16/24/32 бит и float 32/64 бит. Моно и многоканальные файлы преобразуются в стерео. Результат — стерео float32 WAV с частотой исходного файла; исходный файл не перезаписывается. Для полной совместимости эффектов используйте **44,1 или 48 кГц**. Длительность сохраняется, начальная задержка лимитера компенсируется; хвост эффекта после конца исходной записи отдельно не добавляется. Обработка идёт в памяти, поэтому большим файлам требуется достаточно ОЗУ. MP3/FLAC и другие сжатые форматы сначала нужно преобразовать в WAV.

**Поток через виртуальный кабель.** Кабель в комплект не входит. После его отдельной установки направьте звук нужных приложений на виртуальное устройство воспроизведения, например `CABLE Input`. Здесь выберите соответствующее устройство записи `CABLE Output`, а выходом — физические наушники или динамики. Для микрофона/линейного входа достаточно выбрать их непосредственно. Выход не должен возвращаться в тот же вход. Показанная задержка относится к очередям приложения; микшер Windows, драйвер и оборудование добавляют свою задержку.

## Обработка всего звука Windows через APO

Это отдельный режим. Для его настройки остановите виртуальный системный маршрут кнопкой выше на странице «Драйвер».

В `drivers/ViPER4Windows_Setup.exe` находится неизменённый установщик **ViPER4Windows 2.0.1** из [релиза разработчика Windows-драйвера](https://github.com/likelikeslike/ViPER4Windows/releases/tag/2.0.1). Он устанавливает отдельное приложение и аудиоэффект Windows. Пульт теперь проверяет установку и назначение текущему выходу, умеет назначать установленный APO и сохраняет резервную копию настроек этого выхода.

1. Запустите комплектный установщик и завершите установку. Перезагрузите ПК.
2. Полностью закройте установленное приложение, **включая его значок в трее**: одновременно управлять одним APO из двух пультов не следует.
3. В этом пульте откройте **«Драйвер»**. Если текущему выходу APO не назначен, нажмите **«Назначить текущему выходу»** и подтвердите запрос прав Windows. Назначается один эффект MFX, чтобы исключить повторную обработку. При наличии чужого эффекта MFX программа откажется заменять его автоматически. Резервные копии находятся в `data/driver-backups`; кнопка «Отменить назначение» восстанавливает изменённые значения из выбранной копии.
4. Запустите **этот** `ViPER4Windows-RE.exe` от администратора. Можно использовать кнопку «Драйвер → От администратора».
5. На странице «Драйвер» нажмите **«Подключить APO»**, включите «Обработка» и начните воспроизведение музыки.
6. Проверьте ответ драйвера: должно появиться состояние настроенного движка и расти число обработанных кадров. Сообщение «пульт подключён» само по себе ещё не подтверждает обработку звука.

Для системного выхода используйте **48 или 44,1 кГц**. После ответа драйвера пульт адаптирует импульс к сообщённой частоте обработки. Регистрируйте используемый выход; одновременная обработка нескольких выходов с разными частотами этим пультом не гарантируется. Если драйвер не подтверждает обработку, проверьте сведения на странице «Драйвер»: установку DLL, назначение текущему выходу, разрешённые звуковые улучшения и права запуска. Назначение APO и создание канала управления ещё не доказывают, что Windows использует его в текущем аудиопотоке. Совместимость с другими системными эффектами зависит от конкретного выхода и требует отдельной проверки.

## Эффекты и пресеты

Сохранены исходные разделы: Master limiter; Playback gain control; FET compressor; ViPER-DDC; Spectrum extension; FIR equalizer; Convolver; Field surround; Differential surround; Headphone surround+; Reverberation; Dynamic system; Tube simulator 6N1J; ViPER bass; ViPER clarity; Auditory protection; AnalogX; Speaker optimization.

Диапазоны, значения по умолчанию, варианты выбора и зависимости автоматических настроек FET взяты из APK. У эквалайзера 10 полос и диапазон ±12 дБ. Исходный пресет **Flat содержит +1,5 дБ во всех полосах**; для строго нулевой кривой есть отдельная кнопка «0 дБ».

«Пресеты» сохраняют, загружают, переименовывают, перезаписывают, импортируют и экспортируют настройки. **Android XML** соответствует формату SharedPreferences исходного ViPER4Android-RE. JSON — дополнительный формат этого порта; совместимость с новым grouped-JSON v2 других приложений не заявляется.

Файлы **DDC `.vdc` и импульсы `.irs`/`.wav` не входят в комплект**. Выберите их в соответствующих разделах. XML-пресет хранит имена файлов, а не их содержимое: при переносе нужно отдельно скопировать и импортировать нужные DDC/импульсы. Это относится и к переносу обратно на Android, где файлы должны находиться в его каталогах DDC/Kernel под теми же именами.

- DDC должен содержать наборы `SR_44100:` и `SR_48000:` одинаковой длины, по пять коэффициентов на секцию.
- Импульс с другой частотой автоматически пересчитывается к частоте обработки: 48 кГц для входного потока, к частоте исходного WAV для файла, к сообщённой драйвером частоте 44,1/48 кГц для APO. Применяется оконный sinc-фильтр с сохранением суммарного усиления каждого канала.
- Загрузчик WAV принимает импульсы до 20 секунд. Передача импульса системному APO ограничена 2 МБ, то есть примерно 5,4 секунды стерео при 48 кГц.

Настройки хранятся в **`data` рядом с приложением**. Для резервной копии или переноса скопируйте эту папку целиком. Есть отдельные профили «Наушники», «Динамики», «Bluetooth» и профили конкретных выходов Windows. По умолчанию смена выхода Windows переключает соответствующий профиль примерно через две секунды; новый выход получает копию текущих настроек. Во время работы входного потока автоматическое переключение приостановлено. Это поведение можно изменить в «Настройки → Отдельный профиль для каждого выхода Windows».

## Насколько это соответствует оригиналу

Каталог параметров, единицы, преобразования регуляторов, иконки и XML-формат восстановлены из именно приложенного APK 0.6.2. Android-части Magisk, SELinux и AudioEffect заменены средствами Windows. Размещение элементов и шрифты адаптированы к настольному интерфейсу.

Движок собран из [ViPERDSP, commit `db1c11cbe377eb35af6574abe75e3bb009910d88`](https://github.com/likelikeslike/ViPERDSP/tree/db1c11cbe377eb35af6574abe75e3bb009910d88), используемого ViPER4Windows 2.0.1. Более поздний код доводит до рабочего состояния свёртку, объём наушников и FET-компрессор, которые в исходном драйвере 0.6.1 были отключены или незавершены. При этом изменены отдельные алгоритмы, лимитер и порядок эффектов. Поэтому идентичные положения регуляторов могут звучать иначе; побитовое сравнение с Android не выполнено.

7 октября 2026 года проведено дополнительное сравнение с отдельно собранным восстановленным ядром 0.6.1 при **44,1 и 48 кГц**. В отдельных тестах после учёта задержки и исключения начального переходного процесса отсчёты совпали для EQ, DDC, Dynamic System, Spectrum Extension, Differential Surround, Cure, AnalogX, Speaker optimization и Natural/XHiFi Clarity. Это подтверждает сохранение многих алгоритмов на проверенных сигналах и настройках. Это сравнение исходников двух ядер, а не запись выхода Android-устройства.

**Принципы многих эффектов сохранены, но обещать одинаковый характер всего пресета нельзя.** У Bass Natural/Pure, Field Surround, реверберации и лимитера изменена обработка; Tube использует другой алгоритм. В AGC, FET, Convolver и Headphone surround+ современное ядро доводит до работы участки, которые в старом коде не обрабатывали звук или были незавершены. Составные пресеты могут отличаться сильнее из-за порядка эффектов. Если основа вашего пресета — изменённые эффекты, одинаковые положения регуляторов не гарантируют прежнее звучание. Метод, численные результаты и ограничения приведены в [verification/fidelity-audit.md](verification/fidelity-audit.md).

Фактический порядок активных эффектов этого движка: Convolver → Headphone surround+ → DDC → Spectrum extension → EQ → Field surround → Differential surround → Playback gain → FET → Dynamic system → Tube → Bass → Clarity → Auditory protection → AnalogX → Reverb → Speaker optimization → громкость/баланс → лимитер. Дополнительные современные эффекты ViPERDSP, отсутствующие в APK, остаются выключенными.

Лимитер добавляет **256 кадров** задержки: около 5,33 мс при 48 кГц и 5,80 мс при 44,1 кГц. Свёртка, очереди потока и драйвер могут добавлять задержку. AnalogX сохраняет исходное поведение движка: примерно **250 мс тишины** после включения или смены модели, с округлением до границы блока обработки. Встроенные таблицы Headphone surround+ и DDC рассчитаны на 44,1/48 кГц; на других частотах полная цепочка не поддерживается.

## Проверки и состав

Дополнительная проверка на ПК 7 октября: установленный APO совпал с DLL комплектного установщика 2.0.1. После обновления аудиослужбы подтверждены загрузка DLL в audiodg.exe, ответ драйвера на 48 кГц и обработка 233 280 кадров. Подготовлен виртуальный ViPER на FxSound, обработанный звук измерен через loopback физического Realtek. В изолированном тесте бас увеличил уровень 63 Гц примерно на 14,9 дБ, EQ — на 7,9 дБ. При остановленном обработчике виртуальный тестовый сигнал на Realtek отсутствовал. Проверены все три роли выхода Windows, восстановление при остановке и аварийном завершении, −12 дБ громкости и нулевой выход при mute. За 120 с не обнаружено пропущенных кадров или нехватки данных. Первая отметка discontinuity при старте loopback учитывается отдельно. Отчёты находятся в `verification/system-audio-test.json`, `system-audio-volume.json`, `system-audio-soak.json`, `system-audio-watchdog.json` и `machine-driver-test.json`.

В `verification` сохранены отчёты проверок. Проверены реальные изменения отсчётов для эффектов, преобразования параметров, WAV, точный обход при выключенной обработке, загрузка и пересчёт импульсов, DDC, XML/JSON и локальный обмен с APO. Эти проверки не заменяют испытание установленного APO на реальном устройстве и сравнение звучания с Android.

`source` содержит исходники интерфейса, каталог APK, отображение параметров, аудиохост и нативный движок. Для пересборки нужны **.NET 8 SDK**, **Python 3** и **llvm-mingw x64 UCRT**. Из корня этой папки:

```powershell
python source/native/build_native.py C:/tools/llvm-mingw/bin
dotnet publish source/ViPER4Windows.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o build-app
Copy-Item source/native/ViperDsp.dll build-app/ViperDsp.dll
Copy-Item drivers build-app/drivers -Recurse
```

Папка `icons` копируется проектом при публикации. Установщик и компилятор для работы с WAV не нужны. Подробнее о сборке движка — `source/native/NATIVE_NOTES.md`.
